============================

SETUP
-----

Create a working directory, enter it, and source the setup script:

mkdir FluenceStudy
cd FluenceStudy
source /path/to/O2/Detectors/Upgrades/ALICE3/macros/Fluence/SetupFluenceStudyGeant.sh

All the required files will be copied into the current working directory.

FIRST PREPARE
-------------

Run:
    ./00_prepare.sh
or:
    python3 simulation.py prepare

On the first execution, the preparation script copies:

    ${O2_ROOT}/share/Detectors/gconfig/data/rd50_niel.root

to:

    ./rd50_niel.root

It then generates:

    ./rd50_niel.csv

from the damage-weighting graphs stored in `rd50_niel.root`.

Both files remain at the same top level as the code.


TOP-LEVEL FILES AFTER FIRST PREPARE
-----------------------------------

SCORING
-------

The Geant4 scoring macro is:

    scoring_g4_alice3.in

The scoring mesh is named:

    ALICE3

The current scoring quantities are only:

    dose    -> TID
    neq     -> NIEL / 1-MeV neutron-equivalent fluence

The scoring volume dimensions are defined directly in:

    scoring_g4_alice3.in

Only the number of bins in R and Z is overridden at run time.


SCORING BINNING
---------------

Default binning:

    R: 640 bins
    Z: 1000 bins

The defaults correspond to:

    /score/mesh/nBin 640 1000 1

The top-level:

    scoring_g4_alice3.in

is NEVER modified by the run.

Instead, `01_run.sh` copies it into:

    Simulation_files/work/scoring_g4_alice3.in

and modifies only that temporary copy with the requested number of bins.


CHANGE CONFIGURATION
---------------------------
The detector configuration and running options are in 01_run.sh

Search the lines:

CONFIG_KEYS="MIDBase.mLayout=0; Alice3PassiveBase.mMagnetLayout=MagThickRadius; FT3Base.layoutFT3=kSegmented; IOTOFBase.enableBackwardTOF=false; IOTOFBase.enableForwardTOF=false; G4.g4scoring=true; G4.g4fluenceweight=true; G4.fluenceWeightFile=$WORK_DIR/rd50_niel.csv; G4.configMacroFile=$G4_CONFIG; G4.physicsmode=kFTFP_BERT_HP_optical; SimCutParams.lowneut=true; GlobalSimProcs.CUTNEU=5.e-12"

And

o2-sim-serial-run5 \
  --detectorList ALICE3 \
  --skipModules ECL \
  --skipModules FCT \
  --skipModules FD3 \
  --skipModules HALL \
  --skipModules MAG \
  -e TGeant4 \
  -n "$N_EVENTS" \
  -g pythia8pp \
  --seed "$SEED" \
  --configKeyValues "$CONFIG_KEYS"

And modify what you need (note: running with FT3 option FT3Base.layoutFT3=kSegmented)


RECOMMENDED GENERAL COMMAND
---------------------------

Run the complete workflow (here 15000 events, but slow):

    python3 simulation.py all --events 15000 --bins-r 640 --bins-z 1000

This performs:

    prepare
      |
      v
    run
      |
      v
    check
      |
      v
    clean

If `--seed` is omitted, a new time-based random seed is generated automatically for every run.

The bins are referred to Z from -500 to 500 cm and radius from 0 to 320 cm.


CUSTOM BINNING
--------------

For example:

    python3 simulation.py all --events 15000 --bins-r 800 --bins-z 1200

This keeps the same physical scoring volume but changes the mesh granularity.


DIRECT SHELL EXECUTION
----------------------

Default binning and automatic seed:

    ./01_run.sh 15000

Fixed seed:

    ./01_run.sh 15000 123456

Custom scoring binning:

    SCORING_BINS_R=800 \
    SCORING_BINS_Z=1200 \
    ./01_run.sh 15000

Custom scoring binning with fixed seed:

    SCORING_BINS_R=800 \
    SCORING_BINS_Z=1200 \
    ./01_run.sh 15000 123456


FIRST TEST
----------

Before a full production run, a small test can be performed with:

    python3 simulation.py all --events 10 --bins-r 640 --bins-z 1000

The seed is automatically randomized unless `--seed` is explicitly supplied.


OUTPUT ORGANIZATION
-------------------

All temporary files generated by O2 are written under:

    Simulation_files/work/

The final scoring output is copied to:

    Simulation_files/ALICE3.txt

The final geometry is copied to:

    Simulation_files/ALICE3_geometry.root


FINAL OUTPUT AFTER CLEAN
------------------------

After a successful cleanup:

    Simulation_files/
    ├── ALICE3.txt
    └── ALICE3_geometry.root

All other files generated during the simulation are deleted.

The permanent top-level files:

    rd50_niel.root
    rd50_niel.csv

are never removed by the cleanup procedure.


RE-RUNNING
----------

If Simulation_files already contains ALICE3 results, the workflow stops
before overwriting them and prints a warning.

If you want to keep the previous results, rename or move the folder, for example:

    mv Simulation_files Simulation_files_old

Then run the simulation normally.

If instead you want to discard the previous results and replace them:

    python3 simulation.py all --events 15000 --bins-r 640 --bins-z 1000 --force

ANALYSIS
--------

Produce geometry_points.csv from the root geometry file:

    root -l -b -q make_geometry_csv.C

By default it takes the file ./Simulation_files/ALICE3_geometry.root
Source, destination R and Z range can be changed using the arguments of the function.

A geometry_points.csv with the reference geometry is copied anyway with the setup.

Run the Geant4 TID/NIEL analysis with:

    python3 analyze_geant.py

The script reads the simulation output from Simulation_files/ALICE3.txt and produces the TID/NIEL maps, radial profiles, summary tables, and analysis metadata.
To run the analysis on the output in a different folder, just change the name in the script in the working directory.
